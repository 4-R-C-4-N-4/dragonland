# MP recharge and peer-special balance

Approved direction: MP is the sole special resource. A cast consumes the full bar; it refills linearly over that special's recharge time. No separate meter, hit charging, MP cost or cooldown state. Preserve deterministic fixed-step simulation, pause/replay, finite campaign economy and existing saved campaigns. Do not merge/push/commit as part of this change.

1. Replace legacy runtime gates with MP-only recharge. Start battles at zero MP (a full recharge before the first cast), cap at max MP, spend all MP on casting, and expose readiness consistently to AI, input and HUD. Use a positive `rechargeS` data field; normalize legacy frozen special definitions using `cooldownS` so existing v2 campaigns remain readable. Remove obsolete tuning constants and HUD charge indicators/help. Test timing, pause, both sides, capacity independence, full/partial readiness and duplicate queued casts.
2. Build reproducible all-15-special peer diagnostics with identical mixed armies and identical general combat profiles. Exercise both sides with the same AI and seeds, include side-swapped fixtures, record casts, duration, end reason and resource readiness; fail unfinished runs. Compare special families rather than force equal win rates across class-counter armies. Record source/content fingerprints and the before/after definitions. Also use direct-effect budget checks for randomized strikes, wave width/damage, healing, buff uptime and damage-over-time.
3. Tune all 15 definitions with explicit peer trade-offs. In particular: healers must trade healing/protection/mobility/recharge, waves must trade width/damage/recharge rather than strict domination, buffs must trade offense/protection/uptime, and targeted/field/debuff attacks must account for target count and delayed value. Preserve all spell identities. Improve Shepherd's legibility without regenerating art or enlarging every aura indiscriminately.
4. Run parent check/build and independent spec/quality review; fix confirmed findings. Verify MP depletion, refill, pause, readiness and Shepherd feedback in the existing main-repo dev server. Leave only that server running. Record exact results and balance limitations in docs/qa and PROGRESS.md.
